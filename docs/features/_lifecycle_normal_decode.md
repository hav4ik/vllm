# vLLM v1 Single-Sequence Lifecycle (no Spec Decode)

Target: normal (non-speculative) generation on NemotronH / FP8 on H100+sm100 with the FlashInfer attention backend. All citations are against `/workspace/vllm_nemotron3_eagle3/vllm/` at the current checkout. Pipeline-parallel, multimodal, encoder-decoder, LoRA and PD are intentionally skipped.

The path is: HTTP handler -> `AsyncLLM` -> IPC -> `EngineCore.step()` -> `Scheduler.schedule()` -> `GPUModelRunner.execute_model()` + `sample_tokens()` -> `Scheduler.update_from_output()` -> `EngineCoreOutputs` -> `OutputProcessor` -> `RequestOutputCollector` -> `AsyncLLM.generate()` yields -> FastAPI streamer.

## 1. Request entry -> scheduling

**HTTP entry.** An OpenAI-compatible request lands in `vllm/entrypoints/openai/api_server.py`; the running `engine_client` is an `AsyncLLM` (set up at `api_server.py:349`). For chat, the route in `vllm/entrypoints/openai/chat_completion/api_router.py:53` dispatches to `OpenAIServingChat.create_chat_completion` (`vllm/entrypoints/openai/chat_completion/serving.py:204`), which calls `self.engine_client.generate(...)` at `serving.py:315`.

**AsyncLLM.generate -> add_request.** `AsyncLLM.generate` (`vllm/v1/engine/async_llm.py:529`) is an async generator that calls `self.add_request()` (`async_llm.py:288`). That runs `input_processor.process_inputs(...)` (`async_llm.py:356`) to turn the prompt + `SamplingParams` into an `EngineCoreRequest`, creates a `RequestOutputCollector` (`async_llm.py:381`), and forwards to `_add_request` (`async_llm.py:405`), which (a) registers a `RequestState` with the `OutputProcessor` (`async_llm.py:414`), and (b) ships the `EngineCoreRequest` over IPC via `engine_core.add_request_async(request)` (`async_llm.py:417`). A background `output_handler()` task (`async_llm.py:659`) polls the engine-core for outputs and pushes per-request `RequestOutput`s into the collector; `generate()` awaits them in its `while not finished` loop at `async_llm.py:578`.

**EngineCore receives it.** `EngineCore.add_request` (`vllm/v1/engine/core.py:293`) builds a `Request` via `Request.from_engine_core_request(...)` and calls `self.scheduler.add_request(request)`. `Scheduler.add_request` (`scheduler.py:1738`) enqueues it into `self.waiting` and stores it in `self.requests[request_id]`. The engine-core process spins in a busy loop calling `EngineCore.step()` (`core.py:380`).

**`Request` object.** Defined in `vllm/v1/request.py:58`. Starts as `RequestStatus.WAITING` (`request.py:90`). Key fields: `prompt_token_ids`, `_output_token_ids` + `ConstantList` view (`request.py:122`), `num_computed_tokens=0` (`request.py:135`), `block_hashes` (`request.py:165`), `spec_token_ids` (`request.py:134`, empty here). `num_tokens_with_spec = len(_all_token_ids) + len(spec_token_ids)` (`request.py:230`) is the scheduling high-water mark.

**`Scheduler.schedule()`.** Entry at `scheduler.py:348`. It has two back-to-back loops inside one step:

1. RUNNING loop (`scheduler.py:385-551`). For each request currently in `self.running`, `num_new_tokens = num_tokens_with_spec - num_computed_tokens` (`scheduler.py:404`); for a pure decode step this is 1. It calls `self.kv_cache_manager.allocate_slots(request, num_new_tokens, num_lookahead_tokens=0)` at `scheduler.py:463`; if there is no free block for the append, it preempts the lowest-priority running request (`scheduler.py:500`). Accounting updates `num_scheduled_tokens[req_id]` and `req_to_new_blocks[req_id]`.
2. WAITING loop (`scheduler.py:563-850`). It pops the head of `self.waiting`, queries prefix cache via `self.kv_cache_manager.get_computed_blocks(request)` (`scheduler.py:613`), computes `num_new_tokens = request.num_tokens - num_computed_tokens` (`scheduler.py:665`), caps to `token_budget`, then calls `self.kv_cache_manager.allocate_slots(...)` (`scheduler.py:746`) which allocates KV blocks for both the already-hit prefix and the fresh prefill chunk. On success it calls `self.running.append(request)` (`scheduler.py:808`) and sets `request.status = RequestStatus.RUNNING` at `scheduler.py:827` and `request.num_computed_tokens = num_computed_tokens` (prefix-hit count) at `scheduler.py:828`.

The output is a `SchedulerOutput` (`scheduler.py:914`) with `scheduled_new_reqs`, `scheduled_cached_reqs`, `num_scheduled_tokens`, `num_common_prefix_blocks`, and preempted/finished sets. Just before returning, `_update_after_schedule` (`scheduler.py:978`) bumps `request.num_computed_tokens += num_scheduled_token` (`scheduler.py:991`) so the next step's `num_new_tokens` is correctly 1 for a running decoder.

**WAITING vs RUNNING.** `self.waiting` holds requests whose prefill hasn't run (or are preempted); `self.running` holds requests with allocated blocks being stepped every iteration. Promotion WAITING -> RUNNING happens in the WAITING loop once `allocate_slots` succeeds; demotion RUNNING -> PREEMPTED happens via `_preempt_request` (`scheduler.py:956`), which frees its KV blocks and puts it back on the head of `self.waiting`.

## 2. Per-step forward pass

`EngineCore.step()` (`core.py:380`) calls `scheduler.schedule()`, then `model_executor.execute_model(scheduler_output, non_block=True)` (`core.py:392`), waits on the future, calls `sample_tokens(grammar_output)` (`core.py:400`), then `scheduler.update_from_output(...)` (`core.py:405`). For a single-GPU run those executor calls funnel through `Worker.execute_model` -> `GPUModelRunner.execute_model` in `vllm/v1/worker/gpu_model_runner.py:3759`.

**`_update_states`.** At `execute_model` start, `_update_states(scheduler_output)` (`gpu_model_runner.py:1049`) reconciles the persistent `InputBatch`: evicts finished/unscheduled requests, instantiates a `CachedRequestState` for each `scheduled_new_reqs` entry (`gpu_model_runner.py:1146`), and for running requests updates `req_state.num_computed_tokens` (`gpu_model_runner.py:1256`), appends new block ids to `req_state.block_ids` (`gpu_model_runner.py:1293-1302`), and calls `input_batch.block_table.append_row(new_block_ids, req_index)` (`gpu_model_runner.py:1324`).

**`_prepare_inputs`.** Called at `gpu_model_runner.py:3847`; body at `gpu_model_runner.py:1779`. Steps:

- `self.input_batch.block_table.commit_block_table(num_reqs)` (`gpu_model_runner.py:1799` -> `block_table.py:166`) kicks the CPU-to-GPU copy of the block table.
- Builds `req_indices = np.repeat(arange, num_scheduled_tokens)` and a per-request `query_pos` arange via `_get_cumsum_and_arange` (`gpu_model_runner.py:1803-1809`).
- `positions_np = num_computed_tokens_cpu[req_indices] + query_pos` (`gpu_model_runner.py:1812`) is the absolute position for each token slot in the batch.
- `torch.index_select` pulls `input_ids` out of `input_batch.token_ids_cpu_tensor` (`gpu_model_runner.py:1839`) into `self.input_ids.cpu`.
- Builds `query_start_loc` on CPU then `copy_to_gpu()` at `gpu_model_runner.py:1898`.
- Syncs `num_computed_tokens`, `seq_lens = num_computed_tokens + num_scheduled_tokens_gpu` (`gpu_model_runner.py:1996`), and writes the per-token slot mapping via `self.input_batch.block_table.compute_slot_mapping(...)` (`gpu_model_runner.py:2000` -> `block_table.py:141` invokes a Triton kernel that outputs the linear block-slot index for each token position).
- For pure decode (`use_spec_decode = False`), `logits_indices = query_start_loc[1:] - 1` (`gpu_model_runner.py:2042`) - i.e. the last token of each request. Returns `(logits_indices, spec_decode_metadata=None)`.

**Attention metadata (FlashInfer).** `_build_attention_metadata(...)` (`gpu_model_runner.py:3958`) dispatches to each attention group's builder. On sm100+ NemotronH, the backend is `FlashInferBackend` (`vllm/v1/attention/backends/flashinfer.py:317`) and the builder is `FlashInferMetadataBuilder.build` (`flashinfer.py:844`). `build` receives a `CommonAttentionMetadata` containing `query_start_loc`, `seq_lens`, `block_table_tensor`, and `slot_mapping` computed above. It splits the batch into decodes/prefills via `split_decodes_and_prefills` (`flashinfer.py:852`), decides FlashInfer-native vs TRT-LLM kernels (`flashinfer.py:873-895`), builds `paged_kv_indptr/indices` (`flashinfer.py:980`), and plans the decode/prefill wrappers. The result is a per-layer `FlashInferMetadata` stored in `attn_metadata`.

**Forward.** `execute_model` enters `set_forward_context(attn_metadata, ...)` (`gpu_model_runner.py:4006`) then calls `_model_forward(...)` (`gpu_model_runner.py:4023` -> `3480`), which calls `self.model(input_ids=..., positions=..., **model_kwargs)`. Each layer's `Attention.forward` pulls the per-layer `FlashInferMetadata` from the forward context and calls `FlashInferImpl.forward` (`flashinfer.py:1280`), which writes new K/V into the paged KV cache using `attn_metadata.slot_mapping` and runs the paged decode/prefill kernel into the `output` buffer.

**Logits.** After forward: `sample_hidden_states = hidden_states[logits_indices]` (`gpu_model_runner.py:4058`) gathers each request's last-token hidden, then `logits = self.model.compute_logits(sample_hidden_states)` (`gpu_model_runner.py:4059`). Everything needed for sampling is stashed into `self.execute_model_state` (`gpu_model_runner.py:4090`); `execute_model` returns `None` and sampling happens in `sample_tokens`.

## 3. Sampling and bookkeeping

`GPUModelRunner.sample_tokens` starts at `gpu_model_runner.py:4112`. It unpacks `ExecuteModelState` (`gpu_model_runner.py:4134`), optionally applies a grammar bitmask, then calls `_sample(logits, spec_decode_metadata)` (`gpu_model_runner.py:4156`). In the normal (non-spec) path, `_sample` (`gpu_model_runner.py:3308`) takes the `spec_decode_metadata is None` branch and calls `self.sampler(logits=logits, sampling_metadata=...)` (`gpu_model_runner.py:3319`).

`Sampler.forward` (`vllm/v1/sample/sampler.py:68`) optionally computes raw logprobs (`sampler.py:82`), casts to fp32 (`sampler.py:91`), runs argmax-affecting logit processors (`sampler.py:93`), then `self.sample(logits, sampling_metadata)` (`sampler.py:97`) applies temperature/top-k/top-p and draws one token per row. The returned `SamplerOutput.sampled_token_ids` has shape `[num_reqs, 1]` (`sampler.py:140`).

**`_update_states_after_model_execute`.** Called from `sample_tokens` at `gpu_model_runner.py:4158`; body at `gpu_model_runner.py:1404`. For the normal (no-spec) path it early-returns at `gpu_model_runner.py:1415`.

**`_bookkeeping_sync`.** Called at `gpu_model_runner.py:4276`; body at `gpu_model_runner.py:3338`. It CPU-syncs `sampled_token_ids` via `_to_list(...)` (`gpu_model_runner.py:3383`), writes each sampled id into `input_batch.token_ids_cpu[req_idx, start_idx:end_idx]` and bumps `num_tokens_no_spec[req_idx]` (`gpu_model_runner.py:3441-3443`), and appends to the per-request cached state: `req_state.output_token_ids.extend(sampled_ids)` (`gpu_model_runner.py:3447`). The result is packed into a `ModelRunnerOutput` (`gpu_model_runner.py:4311`) and returned to `EngineCore.step`.

**`Scheduler.update_from_output`** (`scheduler.py:1302`, called from `core.py:405`). For each scheduled req_id it looks up the sampled token list (`scheduler.py:1362`); on the non-spec path the rejection block at `scheduler.py:1369` is skipped. `_update_request_with_output` (`scheduler.py:1632`) calls `request.append_output_token_ids(token)` (extending `_output_token_ids`/`_all_token_ids` and `update_block_hashes()` at `request.py:214`) then `check_stop(request, self.max_model_len)` (`scheduler.py:1644`) for EOS, stop tokens, stop strings, and max_tokens. If stopped, `_handle_stopped_request` and `_free_request` (`scheduler.py:1436`) remove the request from `self.requests`, add it to `self.finished_req_ids`, and call `self.kv_cache_manager.free(request)` (`scheduler.py:1843`). An `EngineCoreOutput` with `new_token_ids` and any finish reason is built at `scheduler.py:1463` and bundled into `EngineCoreOutputs`. `num_computed_tokens` was already advanced for the scheduled slice by `_update_after_schedule` (`scheduler.py:991`); no second bump happens in the non-spec path.

## 4. KV block lifecycle

**Allocation on entry to RUNNING.** `KVCacheManager.allocate_slots` (`vllm/v1/core/kv_cache_manager.py:257`) is the single entry point - called from `scheduler.py:746` for new/resumed requests and `scheduler.py:463` for the per-step append. Internally: (a) `coordinator.get_num_blocks_to_allocate` + `block_pool.get_num_free_blocks()` gate-check (`kv_cache_manager.py:387`); (b) for prefix-hit blocks from `get_computed_blocks`, `coordinator.allocate_new_computed_blocks` (`kv_cache_manager.py:397`) bumps `ref_cnt` via `BlockPool.touch` (`block_pool.py:392`); (c) `coordinator.allocate_new_blocks` (`kv_cache_manager.py:404`) ends up calling `BlockPool.get_new_blocks` (`block_pool.py:320`), which pops from `free_block_queue` (`block_pool.py:334`), runs `_maybe_evict_cached_block` (`block_pool.py:352`), and sets `ref_cnt = 1`; (d) with prefix caching, `coordinator.cache_blocks` runs immediately (`kv_cache_manager.py:425`).

**Block table update.** Allocated blocks per request are returned as `req_to_new_blocks[req_id]` and shipped in `SchedulerOutput` as `NewRequestData.block_ids` / `CachedRequestData.new_block_ids`. The worker's `_update_states` calls `input_batch.block_table.append_row(new_block_ids, req_index)` (`gpu_model_runner.py:1324` -> `vllm/v1/worker/block_table.py:102`). The CPU->GPU copy is kicked by `commit_block_table` (`block_table.py:166`) at the top of `_prepare_inputs`, and the per-token `slot_mapping` consumed by FlashInfer is produced each step by the Triton kernel in `compute_slot_mapping` (`block_table.py:141`).

**Prefix-cache promotion.** Each `SingleTypeKVCacheManager.cache_blocks` (`vllm/v1/core/single_type_kv_cache_manager.py:250`) dispatches to `BlockPool.cache_full_blocks` (`block_pool.py:210`), which walks `num_cached_blocks..num_full_blocks`, reads the precomputed `request.block_hashes`, stamps `blk.block_hash = block_hash_with_group_id`, and inserts into `self.cached_block_hash_to_block` (`block_pool.py:271`). This is when a block becomes "cached" and hit-eligible for a future `get_computed_blocks`.

**Free on finish.** `_free_request` (`scheduler.py:1436`) -> `_free_blocks` (`scheduler.py:1841`) -> `kv_cache_manager.free` -> `coordinator.free` -> `SingleTypeKVCacheManager.free` (`single_type_kv_cache_manager.py:276`), which iterates blocks in reverse and calls `self.block_pool.free_blocks(ordered_blocks)` (`block_pool.py:409`). That decrements `ref_cnt`; blocks that reach 0 are appended to `free_block_queue` (`block_pool.py:421`) but keep their `block_hash` - they stay prefix-cache-resident until a future `get_new_blocks` pops one and calls `_maybe_evict_cached_block`.

## 5. Output streaming

`EngineCoreOutputs` is put on an IPC queue back to the `AsyncLLM` process. The background `output_handler()` (`async_llm.py:659`) pulls with `await engine_core.get_output_async()` (`async_llm.py:663`), chunks by `VLLM_V1_OUTPUT_PROC_CHUNK_SIZE`, and calls `self.output_processor.process_outputs(...)` (`async_llm.py:678`).

`OutputProcessor.process_outputs` (`vllm/v1/engine/output_processor.py:572`): (a) updates stats (`output_processor.py:610`); (b) runs `req_state.detokenizer.update(new_token_ids, ...)` (`output_processor.py:627`) where stop-strings may fire a late stop; (c) updates logprobs (`output_processor.py:636`); (d) calls `req_state.make_request_output(...)` (`output_processor.py:639`) which builds a `RequestOutput` with `.finished = finish_reason is not None` (`output_processor.py:278`); (e) pushes onto the per-request queue via `req_state.queue.put(request_output)` (`output_processor.py:652`); (f) if finished, `_finish_request` removes the `RequestState` (`output_processor.py:684`). If detokenizer detected a stop that engine-core didn't, the req_id goes into `reqs_to_abort` and async_llm issues `engine_core.abort_requests_async(...)` (`async_llm.py:690`).

**Delivery.** `AsyncLLM.generate`'s `while not finished` loop at `async_llm.py:578` does `out = q.get_nowait() or await q.get()` and `yield out` (`async_llm.py:589`); when `out.finished` is `True` the generator exits. The FastAPI chat path (`chat_completion/serving.py:343`) either aggregates via `chat_completion_full_generator` or pumps via `chat_completion_stream_generator`, writing each `RequestOutput` as an SSE chunk to the `StreamingResponse`. Client disconnect cancels the generator; `AsyncLLM.generate` catches `CancelledError` at `async_llm.py:594` and calls `self.abort(...)`, eventually reaching `Scheduler.finish_requests(..., FINISHED_ABORTED)` (`scheduler.py:1760`), which releases KV blocks through the same `_free_request` path.

**State transition summary.** `WAITING` -> scheduler allocates -> `RUNNING` (`scheduler.py:827`); each step decodes one token, advancing `num_computed_tokens`; on stop, `_update_request_with_output` trims, `_handle_stopped_request` sets `FINISHED_STOPPED` / `FINISHED_LENGTH_CAPPED` (see `RequestStatus` at `request.py:295`); `_free_request` frees blocks and marks the id in `scheduler.finished_req_ids`, which the next `SchedulerOutput` echoes so the worker's `_update_states` (`gpu_model_runner.py:1060`) evicts it from the `InputBatch`. `OutputProcessor._finish_request` then drops the API-side `RequestState`, closing the lifecycle.
